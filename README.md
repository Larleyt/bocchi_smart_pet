# Bocchi Smart Pet

Нативное приложение для macOS 14+: Боччи ищет место вне текста и элементов управления, остаётся поверх окон, реагирует на клик и переносится мышью. За пределами фигурки клики проходят в приложение под ней. Исходники и окружение сборки находятся в этом проекте. Внешних библиотек нет.

## Сборка и запуск

Нужны Apple Command Line Tools с Swift 6.3 и macOS SDK:

```sh
./scripts/build-app.sh
open "dist/Bocchi Smart Pet.app"
```

Сборка использует постоянный локальный сертификат из игнорируемого `.local-signing/`: тот же signer и bundle ID сохраняются при изменении бинарника. Скрипт использует системные `/usr/bin/python3`, OpenSSL и `security`, не требует Apple Developer и не добавляет сертификат в системное доверие. Отдельный keychain проекта временно включается в user search list на время подписи, затем удаляется из списка и блокируется. TCC и автозапуск не меняются.

Сохраните `.local-signing/` в защищённой резервной копии: там ключ подписи и пароль keychain, их нельзя коммитить или отправлять. Потеря этих файлов означает новую идентичность и повторную выдачу разрешений. Это локальная подпись для этого Mac; Developer ID/notarization для распространения не настроены.

При запуске и повторном открытии `.app` появляется окно настройки. После наблюдаемой выдачи Accessibility окно закрывается автоматически; уже разрешённую настройку можно закрыть кнопкой «Закрыть и начать». Настройку также можно вернуть через меню **♪**.

## Разрешения

Разрешение выдаётся **Bocchi Smart Pet** (`local.bocchi.smartpet`), запущенному из `dist/Bocchi Smart Pet.app`. В его окне настройки показан реальный путь и есть кнопка открытия в Finder. Если приложения нет в списке Privacy & Security, добавьте его через «+» по этому пути. После выдачи доступа система может попросить перезапуск.

При переходе со старой ad-hoc сборки одной включённой галочки недостаточно: запись может принадлежать старой подписи. В Accessibility удалите старую **Bocchi Smart Pet** кнопкой «−», добавьте текущую `.app` через «+», включите её и перезапустите. Это разовая замена старой записи; повторный запрос внутри приложения не исправляет её. Подробности диагностики — [T-4](docs/tasks/T-4-permission-identity.md).

Основной режим использует **Accessibility**: читает типы, доступные действия и границы опубликованных элементов без значений текста, URL и названий документов. Доступ macOS к Accessibility широкий; приложение использует его только для чтения геометрии и уведомлений. Screen Recording для этого режима не требуется.

**Визуальная проверка выключена по умолчанию.** Включать её и выдавать Screen Recording нужно только для интерфейсов, которые недостаточно описывают себя через Accessibility. Два разрешения показываются отдельно. Кнопка запроса разрешения и кнопка открытия настроек — разные действия. Закройте окно настройки кнопкой «Закрыть и начать», чтобы начать поиск.

Запрос разрешения для **ChatGPT** не нужен для работы Боччи и может быть отклонён. Собственная визуальная проверка Боччи тоже необязательна; аудио отключено в её конфигурации захвата.

## Как выбирается место

Сначала читаются геометрия окон и карта элементов Accessibility. Первая посадка предпочитает боковые поля на средней высоте с отступом от системной кромки, избегая типичных верхних и нижних зон управления при наличии альтернативы. Это эвристика, а не распознавание назначения фона: каждый участок проходит AX или локальную визуальную проверку. Изменение карты вызывает проверку прежней позиции; пока она безопасна, координаты сохраняются. Если переезд нужен, выбирается ближайшая свободная точка к прежнему месту на ограниченной сетке (обычно шаг4pt), а не самый большой дальний карман. Смена физического экрана или доступности визуального режима сбрасывает эталон. Известные тексты, кнопки и поля становятся препятствиями. Нажимаемые группы защищаются по всей рамке, даже если браузер не называет их кнопками. Обычные изображения и canvas остаются неизвестными областями для визуальной проверки. Неизвестный интерфейс и неописанный рабочий стол не считаются пустыми. При недостатке сведений без визуальной проверки Боччи скрывается.

После прокрутки или перетаскивания, включая среднюю кнопку мыши, Боччи остаётся видимой и запрашивает свежую проверку своего участка. Само событие не запрещает прежнее место: на неизменном свободном фоне координаты сохраняются. Устаревший асинхронный результат и изменение рабочей области из-за Dock не скрывают последнюю безопасную позицию. Новая подтверждённая преграда, ошибка анализа или отсутствие места по-прежнему могут скрыть её. Рабочее пространство, физический экран и разрешения обрабатываются как смена условий доступа; переключение активного приложения запускает мягкую перепроверку. Контракт — [T-10](docs/tasks/T-10-quiet-interaction.md), история исправления scroll — [T-9](docs/tasks/T-9-stable-scroll.md).

При наведении Боччи смотрит на курсор. Клик запускает существующие кадры взгляда вниз на толстовку; перетаскивание двигает само окно без активации приложения. После отпускания выбранное место проверяется; если оно занято, питомец ищет ближайшее безопасное. Непрерывное наведение без нажатия пять секунд вызывает побег. Координаты окна меняются плавно, одновременно проигрываются существующие кадры бега вправо/влево. Клик/перетаскивание начинают новый отсчёт наведения после отпускания. Этот набор T-10 использует прежние кадры. Направленные прыжки и наклоны [T-11](docs/tasks/T-11-directional-animation.md) остаются отдельным следующим набором.

На свободном видимом верхнем краю обычного окна Боччи может подойти спереди и сесть, свесив ноги. Для опоры сохраняются ID окна и исходная рамка: при перемещении окна она следует за ним без повторного подъёма; при потере края возвращается к свободному размещению. Проверяется вся область тела и ног, включая текст, кнопки и передние окна. Для неизвестной области нужен прежний visual opt-in; из детализации исключается только2pt полоса подтверждённой границы, OCR остаётся полным. Фигура при сидении занимает128×156 вместо обычных84×156. Прозрачный шум и отдельные фрагменты соседних кадров удаляются при загрузке, чтобы они не светились и не перехватывали мышь. Контракт, исходники кадров и проверка — [T-13](docs/tasks/T-13-climb-and-perch.md). В fullscreen без доступного края действует обычное свободное размещение; панели сайтов — [T-14](docs/tasks/T-14-element-supports.md).

При включённой визуальной проверке проверяются до трёх небольших участков-кандидатов; уже описанный AX-кандидат не требует снимка. Если локальная проверка не нашла место, используется известная AX-альтернатива. Только если её тоже нет, допускается один полный кадр активного дисплея и до трёх локальных проверок кандидатов по этой карте. Найденные локальные преграды исключаются при следующих попытках; эталоном становится проверенный свободный участок. Действует предел один полный кадр за 10 секунд. Если он временно недоступен из-за этого предела, отложенный поиск возобновляется после срока. После действительно исчерпанного поиска Боччи ждёт изменения сцены или взаимодействия; таймер не повторяет полные кадры бесконечно. Это может оставить её скрытой дольше на интерфейсе без Accessibility-событий. Визуальная карта сохраняет свободные промежутки внутри связанных контуров интерфейса; исправление ложного запрета всего экрана описано в [T-12](docs/tasks/T-12-hidden-search.md).

На спокойном экране под Боччи проверяется только её участок раз в 5 секунд; после ввода или системного уведомления свежая проверка выполняется раньше. Изменение не менее 10% пикселей с допуском цветового шума считается сигналом активности, но не доказывает наличие кнопки; неподвижный обнаруженный текст или кнопка всё равно запрещают размещение. Свои окна и курсор исключаются из снимка. В памяти хранится небольшой RGB-эталон, кадры и распознанный текст не сохраняются и не отправляются в сеть. Глобальные нажатия клавиш приложение не отслеживает.

Полнота Accessibility зависит от приложения; пользовательский canvas может остаться неизвестным. Пиксельный анализ тоже не гарантирует распознавание любого интерфейса. При действующей ошибке анализа или отсутствии уверенного места Боччи скрывается. Устаревший результат отбрасывается без изменения последней безопасной позиции. Меню **♪**: пауза, настройка доступа и выход.

## Проверка

```sh
./scripts/check.sh
```

Перед проверкой завершите работающую Боччи через меню **♪**: LaunchServices должен направлять повторное открытие тестовому экземпляру. Скрипт выполняет XCTest, `--self-test` реального executable, release-сборку `.app`, проверку подписи на разных Mach-O и `--launch-check` через LaunchServices. Последняя проверка открывает и закрывает собственное окно настройки, затем возвращает его настоящей командой `open`, в том числе при видимой pet panel. Для XCTest нужен test runtime установленного `/Applications/Xcode.app`; скрипт проверяет его наличие и запускает runner напрямую, без изменения глобального `xcode-select` и принятия лицензии.

Runtime-проверки кратко показывают собственные тестовые окна AppKit. Внешние AX/захват/время заменяются явно названными fixtures; настоящий OCR, карта препятствий, выбор места, жизненный цикл и NSPanel остаются рабочими. Логи и изображения собственных fixtures лежат в игнорируемом `artifacts/`. Результаты и оставшаяся проверка чужих окон описаны в [T-2](docs/tasks/T-2-minimal-capture.md).

Для диагностики есть аргумент `--diagnose-placement`: обычный поиск запускается сразу, визуальный fallback запрещён, а изменения исхода и счётчики AX пишутся в stderr без текста/URL/пикселей. Реальный AX-only показ и исправление структурных групп с рамкой 0×0 описаны в [T-5](docs/tasks/T-5-live-placement.md).

`--trace-placement` запускает поиск с обычной сохранённой visual preference и без стартового setup. Он пишет тип content-movement события (не чаще двух раз в секунду), смены позиции/исхода, причины сброса activity areas, реальные permission booleans, границы проверенного участка и крупнейшего визуального препятствия в stderr; клавиши, текст, URL и пиксели в trace не пишутся. В отличие от AX-only диагностики этот режим не запрещает opt-in visual fallback. Подробности изменения выбора места — [T-7](docs/tasks/T-7-live-pan.md).

В trace mode теперь видны причины AX unknown, включая пустой container, неподдерживаемые children и прерывание обхода. Диагностика конкретного полноэкранного окна и необходимый ручной шаг для visual fallback записаны в [T-8](docs/tasks/T-8-fullscreen-accessibility.md).
