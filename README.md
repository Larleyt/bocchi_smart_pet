# Bocchi Smart Pet

Нативное приложение для macOS 14+: Боччи ищет место вне текста и элементов управления, остаётся поверх окон и пропускает клики. Исходники и окружение сборки находятся в этом проекте. Внешних библиотек нет.

## Сборка и запуск

Нужны Apple Command Line Tools с Swift 6.3 и macOS SDK:

```sh
./scripts/build-app.sh
open "dist/Bocchi Smart Pet.app"
```

Сборка использует постоянный локальный сертификат из игнорируемого `.local-signing/`: тот же signer и bundle ID сохраняются при изменении бинарника. Скрипт использует системные `/usr/bin/python3`, OpenSSL и `security`, не требует Apple Developer и не добавляет сертификат в системное доверие. Отдельный keychain проекта временно включается в user search list на время подписи, затем удаляется из списка и блокируется. TCC и автозапуск не меняются.

Сохраните `.local-signing/` в защищённой резервной копии: там ключ подписи и пароль keychain, их нельзя коммитить или отправлять. Потеря этих файлов означает новую идентичность и повторную выдачу разрешений. Это локальная подпись для этого Mac; Developer ID/notarization для распространения не настроены.

При запуске и повторном открытии `.app` появляется окно настройки. После наблюдаемой выдачи Accessibility окно закрывается автоматически; уже разрешённую настройку можно закрыть кнопкой «Закрыть и начать». Настройку также можно вернуть через меню **♪**.

## Разрешения

Разрешение выдаётся **Bocchi Smart Pet** (`local.bocchi.smartpet`), запущенному из `dist/Bocchi Smart Pet.app`. В его окне настройки показан реальный путь и есть кнопка открытия в Finder. Если приложения нет в списке Privacy & Security, добавьте его через «+» по этому пути. После выдачи доступа система может попросить перезапуск.

При переходе со старой ad-hoc сборки одной включённой галочки недостаточно: запись может принадлежать старой подписи. В Accessibility удалите старую **Bocchi Smart Pet** кнопкой «−», добавьте текущую `.app` через «+», включите её и перезапустите. Это разовая замена старой записи; повторный запрос внутри приложения не исправляет её. Подробности диагностики — [T-4](docs/tasks/T-4-permission-identity.md).

Основной режим использует **Accessibility**: читает типы и границы опубликованных элементов без значений текста, URL и названий документов. Доступ macOS к Accessibility широкий; приложение использует его только для чтения геометрии и уведомлений. Screen Recording для этого режима не требуется.

**Визуальная проверка выключена по умолчанию.** Включать её и выдавать Screen Recording нужно только для интерфейсов, которые недостаточно описывают себя через Accessibility. Два разрешения показываются отдельно. Кнопка запроса разрешения и кнопка открытия настроек — разные действия. Закройте окно настройки кнопкой «Закрыть и начать», чтобы начать поиск.

Запрос разрешения для **ChatGPT** не нужен для работы Боччи и может быть отклонён. Собственная визуальная проверка Боччи тоже необязательна; аудио отключено в её конфигурации захвата.

## Как выбирается место

Сначала читаются геометрия окон и карта элементов Accessibility. Известные тексты, кнопки, поля и изображения становятся препятствиями. Неизвестный интерфейс и неописанный рабочий стол не считаются пустыми. При недостатке сведений без визуальной проверки Боччи скрывается.

При включённой визуальной проверке проверяются до трёх небольших участков-кандидатов. Только если их недостаточно, допускается один полный кадр активного дисплея и один локальный кадр для эталона выбранного места. Полный кадр не повторяется по таймеру; действует дополнительный предел один раз за 10 секунд. Если поиск исчерпан, Боччи ждёт изменения сцены или взаимодействия. Это может оставить её скрытой дольше на интерфейсе без Accessibility-событий.

Под Боччи проверяется только её участок раз в 5 секунд. Изменение не менее 10% пикселей с допуском цветового шума означает активность; неподвижный текст или кнопка всё равно запрещают размещение. Свои окна и курсор исключаются из снимка. В памяти хранится небольшой RGB-эталон, кадры и распознанный текст не сохраняются и не отправляются в сеть. Глобальные нажатия клавиш приложение не отслеживает.

Полнота Accessibility зависит от приложения; пользовательский canvas может остаться неизвестным. Пиксельный анализ тоже не гарантирует распознавание любого интерфейса. При ошибке, устаревшем результате или отсутствии уверенного места Боччи скрывается. Меню **♪**: пауза, настройка доступа и выход.

## Проверка

```sh
./scripts/check.sh
```

Перед проверкой завершите работающую Боччи через меню **♪**: LaunchServices должен направлять повторное открытие тестовому экземпляру. Скрипт выполняет XCTest, `--self-test` реального executable, release-сборку `.app`, проверку подписи на разных Mach-O и `--launch-check` через LaunchServices. Последняя проверка открывает и закрывает собственное окно настройки, затем возвращает его настоящей командой `open`, в том числе при видимой pet panel. Для XCTest нужен test runtime установленного `/Applications/Xcode.app`; скрипт проверяет его наличие и запускает runner напрямую, без изменения глобального `xcode-select` и принятия лицензии.

Runtime-проверки кратко показывают собственные тестовые окна AppKit. Внешние AX/захват/время заменяются явно названными fixtures; настоящий OCR, карта препятствий, выбор места, жизненный цикл и NSPanel остаются рабочими. Логи и изображения собственных fixtures лежат в игнорируемом `artifacts/`. Результаты и оставшаяся проверка чужих окон описаны в [T-2](docs/tasks/T-2-minimal-capture.md).

Для диагностики есть аргумент `--diagnose-placement`: обычный поиск запускается сразу, визуальный fallback запрещён, а изменения исхода и счётчики AX пишутся в stderr без текста/URL/пикселей. Реальный AX-only показ и исправление структурных групп с рамкой 0×0 описаны в [T-5](docs/tasks/T-5-live-placement.md).
