# T-12 — восстановление показа после «Закрыть и начать»

Запрос: после закрытия настройки фигурка не появляется. Проверено до правок: процесс81745 работает, AX=true/screen=true/visualOptIn=true, но журнал artifacts/t10-speed-live.log повторяет noSpace с position=nil. Кнопка скрывает настройку и возобновляет heartbeat; сбой находится в поиске места. Новый диагностический запуск93160 временно показал питомца, затем снова скрыл. Его полный визуальный map вернул obstacle точно размером с экран1512×982 (artifacts/t12-diagnostic-live.log), хотя локальная проверка перед этим нашла пустой участок справа.

Причины: visualDetailRects склеивает связные ячейки в bounding box и заполняет свободные внутренности сложного контура; PlacementSession ставит searchExhausted до проверки10s лимита полного кадра, поэтому отложенный поиск без нового внешнего события не возобновляется после срока.

Контракт до исправления: реальный ScreenAnalyzer на синтетическом связном контуре сохраняет занятые границы и свободную внутреннюю область для реального PlacementEngine; на старом коде assertion должен быть red. Реальный PlacementSession/native overlay с fake только внешних pixels/AX/времени проходит initial origin→полный занятый map→новая сцена в cooldown→ожидание без повторных captures→автоматический отложенный поиск после10s→показ проверенного участка. До срока нельзя снимать полный кадр; после фактически исчерпанной карты таймер не должен запускать бесконечные full captures. Старый код обязан дать red на восстановлении.

Границы: существующие разрешения, opt-in и audio=false сохраняются; захват только самим Bocchi Smart Pet, геометрический trace без текста/сохранения снимков. Новые анимации/T-11 не входят. Приложение остаётся в dist. После red/green — полный scripts/check.sh, независимое ревью, подписанный native запуск с проверкой разрешений и окна.

## Проверка и остаток

В ScreenAnalyzer связные bounding boxes заменены горизонтальными непрерывными полосами занятых ячеек: каждый обнаруженный участок сохраняется, а пустота внутри контура больше не превращается в препятствие. Проход линейный по прежней сетке максимум96×64, без flood-fill очереди. Порог контраста/деталей и OCR не изменены. PlacementSession различает готовый, отложенный до срока и действительно исчерпанный поиск. До срока нет повторных захватов, после срока можно закончить отложенный поиск; действительно исчерпанная полная карта по-прежнему ждёт внешнего изменения. Непосредственно перед публикацией кандидат проверяется локально, strict freshness/generation остаются.

До исправления cooldown-сценарий дал **119 passed / 1 failed** на восстановлении без нового ввода (artifacts/t12-cooldown-baseline-red.log). Связная светлая рамка на тёмном фоне в отрицательных координатах через реальный ScreenAnalyzer и PlacementEngine дала **32 passed / 1 failed** на свободной внутренней области (artifacts/t12-visual-baseline-red.log). Оба assertion входят в итоговый gate.

Полный `./scripts/check.sh` exit0: **22 XCTest + 129 runtime + 8 signing + 6 LaunchServices = 165 проверок, 0 failures** (artifacts/t12-final-check.log). LaunchServices дополнительно нажимает настоящую кнопку «Закрыть и начать» через performClick и проверяет закрытие настройки; последующий reopen возвращает то же окно. Это отдельная проверка действия кнопки: показ после неё проверяется на Session/native panel с явными внешними fixtures. SHA7 критических source/test-файлов сохранены в artifacts/t12-source-sha256.txt.

Подписанная .app запущена через LaunchServices из dist с сохранёнными разрешениями: AX=true/screen=true/visualOptIn=true. Три локальных проверки отвергли занятые области, затем нашли свободный crop и показали panel. Повторные свежие проверки с delta=0.000 сохраняют точку (artifacts/t12-final-live.log). Новых разрешений не запрашивали, снимков/текста в журналы не записывали.

Последующее смешанное30s наблюдение собственного окна дало560 выборок,91visible/469absent, один переезд (artifacts/t12-own-panel-watch.log). Во время настоящего scroll появились подтверждённые локальные преграды, после чего полная карта уже без ложного bbox предложила кандидат(1216,489); точный crop обнаружил дополнительную деталь, и единственная попытка по карте вернула noSpace. Поэтому165/0 не считается окончательной приёмкой T-12. Дополнительный контракт до правки: после отказа локального кандидата по полной карте проверять следующие ближайшие с учётом уже известных отказов, максимум3, без повторного полного снимка. Реальный Session/native overlay с явно названным внешним coarse-map fixture должен дать red на прежнем единственном кандидате и green на втором, сохранив один полный кадр.

Итоговый поиск по полной карте учитывает отказы начальных локальных проверок и допускает до3 точных локальных кандидатов по той же карте. Каждый отказ добавляет реальные obstacle bounds в следующий nearest-поиск; публикация возможна только после успешного свежего локального результата. Полный кадр не повторяется. Для регрессии использована допустимая узкая рабочая полоса: это исключает альтернативные вертикальные пути и проверяет именно переход ко второму ближайшему кандидату. Точечное ограничение цикла одной попыткой даёт **122 passed / 1 failed** (artifacts/t12-map-retry-baseline-red.log); рабочий код с3 попытками требует6 captures:3 начальных,1 полный,2 локальных по карте, и принимает второй кандидат.

Окончательный `./scripts/check.sh` exit0: **22 XCTest + 130 runtime + 8 signing + 6 LaunchServices = 166 проверок, 0 failures** (artifacts/t12-map-retry-final-check.log). Подписанная итоговая .app запущена из dist: AX=true/screen=true/visualOptIn=true, panel показана, затем свежие проверки delta=0.000 (artifacts/t12-map-retry-live.log).
