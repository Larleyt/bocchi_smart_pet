# T-19 — стабильное наведение и побег через пять секунд

Запрос 16.10.2026 после T-17: стоящая Боччи убегает только при наведении точно
по центру; в других точках головы/тела дёргается и мигает. Рабочая ветка —
`codex/run-and-front-seat`.

## Скоуп файлов

`Overlay.swift`, `InteractionCheck.swift`; при доказанной необходимости —
`PetInteraction.swift`, `App.swift`, `PlacementSession.swift` и их проверки.
Канон: этот task и `BACKLOG.md`.

## Приёмка и проверка

- Настоящий курсор/таймер → `SpriteView.tick` → hover event → session escape →
  выбор свободной позиции → видимое движение `PetOverlay`.
- На видимой голове/теле, в том числе вне центра, стоя и сидя: один побег после
  пяти секунд. До порога движения нет; прозрачное поле не вызывает побег.
- Повторная проверка безопасного места не меняет отрисованный кадр, не сбрасывает
  наведение и сохраняет работу click/drag, скрытия, движения и посадки.
- RED до исправления и GREEN после него; для critical path допустимы только
  внешние fake-границы времени, указателя и AX/capture.
- Независимое ревью, `scripts/check.sh`, native smoke подписанной сборки,
  сохранение разрешений, отдельный чистый commit.

## Исправление мигания, 16 октября

Подтверждённое мигание: `PlacementSession.refresh` повторно публиковал то же
место, а `PetOverlay.publish` каждый раз вызывал `sprite.stand()`. Направленный
взгляд на срок до следующего 50 ms тика заменялся исходным кадром. Исправление:
видимая неподвижная стоящая Боччи в той же позиции сохраняет текущий кадр.
Проверенная позиция после drag по-прежнему включает ввод. Движение, посадка,
скрытие и новая позиция проходят обычный путь публикации.

Гипотеза о перевёрнутой alpha-маске опровергнута независимой marker-калибровкой:
исходный `flipped: true` совпадает с отрисовкой и не изменён. На сетке из
52 559 точек нет пропущенных полностью непрозрачных пикселей головы/тела.

На промежуточной версии сбой побега вне центра отдельно не воспроизведён.
Сам сброс кадра не обнуляет hover таймер: gaze восстанавливается до alpha-hit следующего тика. Поэтому исправление
мигания нельзя считать доказанным исправлением отдельного отказа побега.

## Исправление отказа побега, 17 октября

Дефект повторился: Боччи остаётся видимой на месте.
Живой журнал подтвердил распознавание
hover на голове/теле вне центра; само событие не гарантировало смену позиции.

Два дефекта воспроизведены через настоящий `SpriteView.tick` → hover event →
`PlacementSession` → `PetOverlay`/NSPanel. Внешние fake-границы — часы, указатель,
AX snapshot, результаты capture и их актуальность; внутренних моков нет.

1. `refresh` сбрасывал `relocationPending` до завершения async capture.
   Если capture устаревал, следующий несвязанный с Боччи сдвиг списка окон
   очищал `activityAreas`. Повторная проверка считала исходное место допустимым
   и оставляла Боччи там, даже с курсором над ней. Заявка на побег терялась.
2. `escape` записывал добровольно покинутые места в `activityAreas`, хотя
   активности контента там не было. В сцене с двумя свободными местами первый
   побег проходил, а второй и третий ошибочно завершались `noSpace`.

Исправление в `PlacementSession`: отдельно хранится исходная позиция текущего
побега (`pendingEscapeOrigin`). Она запрещена до принятого перемещения/показа,
переживает stale capture, soft invalidate и `noSpace`, но отменяется hard reset
или ручным drag/drop. Предыдущие добровольные места можно использовать снова.
`activityAreas` сохраняет только реальные изменения пикселей; запреты текста,
препятствий и неизвестного содержимого не ослаблены. Порог остаётся пять секунд.

## Blocked / deferred

Ручная приёмка побега закрыта. Положительные
проверки вне центра не означают, что любое окружение имеет безопасное место:
при настоящем отсутствии места действует прежнее безопасное скрытие `noSpace`.

T-18 AX-only отложена отдельно. Новый арт, изменение
пятисекундного порога, TCC, перенос .app, host capture и обход препятствий на всём
маршруте в эту задачу не входят.
