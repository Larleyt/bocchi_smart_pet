# T-1 — Боччи выбирает свободное место на Mac

Исходный этап. Актуальный режим получения данных и разрешений описан в [T-2](T-2-minimal-capture.md).

## Запрос

Отдельное локальное приложение с уже созданной Боччи. Питомец располагается в свободной от текста и элементов управления области поверх приложений Mac. Исходники, окружение и проверяемая сборка находятся в этом проекте.

## Минимальный результат

- Нативное приложение в строке меню, прозрачная анимация Боччи, не перехватывающая клики и фокус.
- Локальный анализ снимка активного дисплея: Vision OCR, геометрия доступных элементов Accessibility и консервативная маска визуальных деталей.
- Выбор места с отступом от препятствий и указателя; сохранение безопасной позиции. Если места нет, анализ устарел или захват не удался — питомец скрыт.
- Пересчёт при смене приложения/экрана/Space, вводе и прокрутке, плюс периодическая проверка изменений без ввода. Устаревший результат не публикуется после нового события.
- Окружение без внешних библиотек: SwiftPM + установленные Apple SDK. Сборка .app воспроизводима командой из README.
- Пиксели и распознанный текст не записываются и не отправляются в сеть при обычной работе.

## Критический путь и проверка до реализации

Реальный вход: исполняемый файл приложения, обычный запуск и режим `--self-test`. Внутренний путь: изображение/AX-прямоугольники → реальный анализатор → карта препятствий → PlacementEngine → реальный NSPanel и его frame/visibility. Наблюдаемый результат: frame внутри рабочего дисплея, не пересекает известные текст/кнопки с отступом; на плотном экране panel скрыт; после нового события старый анализ не показывает panel.

В автоматической проверке внешние границы захвата экрана, чужого Accessibility, времени и координат указателя заменяются явно названными fixture/fake. Визуальные fixtures рисуются настоящими AppKit-контролами; OCR, построение маски, выбор позиции и обновление NSPanel остаются настоящими. Отдельно выполняются unit-проверки геометрии, отрицательных координат мониторов, отсутствия места, инерции позиции и плотных сцен.

Чувствительность проверяется целевой временной мутацией допуска перекрытий в PlacementEngine: тот же runtime self-test обязан стать красным, после восстановления кода — зелёным. Логи и отчёт сохраняются в artifacts/. Обязательные проверки не skip-аются. Независимое ревью проверяет путь, допущения, приватность, устаревшие async-результаты и red/green.

## Границы

Существующий Pets-клиент не модифицируется. Системные разрешения выдаёт пользователь средствами macOS; приложение не меняет TCC и не обходит отказ. Полная гарантия распознавания любых нестандартных интерфейсов не заявляется. Реальная работа с чужими окнами требует отдельного smoke после выдачи разрешений; до него нельзя считать проверенным весь системный сценарий.

## Контракты модулей

- `BocchiCore`: только стандартные Swift-типы, без AppKit/Vision/I/O. `PetPoint(x:y:)`, `PetSize(width:height:)`, `PetRect(x:y:width:height:)` с Double и Sendable/Equatable; Rect: maxX/maxY, intersects/contains. `PlacementEngine.choose(in: PetRect, avoiding: [PetRect], size: PetSize, previous: PetRect?) -> PetRect?`. Отступ 12 pt; безопасная previous сохраняется. Исходное предпочтение нижнего правого участка заменено новым выбором свободной области в [T-7](T-7-live-pan.md). Ограниченная сетка/интегральная маска, без кубического перебора по числу OCR-прямоугольников.
- `ScreenAnalyzer`: адаптер Foundation/CoreGraphics/ScreenCaptureKit/Vision/ApplicationServices. `struct ScreenSnapshot: Sendable { let obstacles: [PetRect]; let controlsAvailable: Bool; let pixelWidth: Int; let pixelHeight: Int }`. `actor ScreenAnalyzer`: `func capture(displayID: UInt32, screenBounds: PetRect, frontmostPID: Int32?, ownBundleID: String) async throws -> ScreenSnapshot` и `func analyze(image: CGImage, screenBounds: PetRect, controls: [PetRect] = []) throws -> ScreenSnapshot` для того же пути с внешним fixture захвата. Глобальные Quartz-координаты, origin сверху слева. Обычный захват исключает своё приложение, курсор и не сохраняет image/text. AX-обход ограничен по числу узлов и времени; ошибки диагностируются, OCR не подменяется пустым успешным результатом.
- Корневой исполнитель владеет AppKit UI, координатным преобразованием, жизненным циклом, async-публикацией, runtime self-test, упаковкой и документацией. Результаты публикуются только при совпадении поколения и разрешённой видимости.
